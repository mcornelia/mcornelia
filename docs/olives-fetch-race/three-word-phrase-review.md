# Access phrase format and visible feedback — unpublished

The iPhone report was reproduced with dummy data in mobile WebKit. Save dispatched the submit event and native validation passed; there is no HTML pattern on these inputs. The old handler rejected the continuous word but supplied only a generic bottom-of-form message, without field focus or invalid-field marking. Empty required fields could separately prevent submission through native validation.

The form now uses explicit validation with inline alerts, aria-invalid/describedby, focus and scroll to the invalid field, and retained entries. Server or network errors focus and reveal the status message. No invalid-format request is sent. Native required fields remain semantically marked, while novalidate ensures the application's visible feedback handles blank entries too.

New replacements require exactly three alphabetic words separated by dashes, then one or more digits and ! immediately after the third word, up to the existing 160-character limit. Uppercase and typographic dashes normalize; whitespace-only separators do not satisfy the new format. Huck and Olive are optional choices, not per-player restrictions. The UI briefly notes that shorter phrases are easier to guess and should be unique to this casual game. No phrase is assigned or prefilled.

Sign-in still accepts published opaque keys exactly and all previously supported six-to-twelve-word phrases, including their original normalization. New replacement validation is separate from login compatibility. Existing salted verifiers, hashing, storage, player ownership checks, throttling, and lost-response recovery are unchanged. A replacement only takes effect when its owner supplies their current credential, enters and confirms their own new phrase, and presses Save.

Validation uses only disposable local credentials/state: access unit/integration tests cover the new syntax, invalid requests, legacy environment credentials and existing salted phrase verifiers, player isolation, duplicate requests, restart persistence, and exact game-state preservation. Mobile browser checks cover malformed and blank fields, mismatch, focus, inline feedback in a 393×380 keyboard-sized viewport, retained values, no invalid writes, wrong-player current key, successful new-format save, duplicate submit and lost response/reload recovery. Readability checks cover 393×852, 390×844, 200% text size and safe areas.

Publication requires separate approval for both the Fetch Race Worker (validation change) and GitHub Pages (form, guidance, feedback, cache versions). Deploy the Worker first, then Pages, using existing bindings/secrets and no migrations, reset, credential rotation, or real access-change requests. Cached old forms proposing six words receive a validation error; existing sign-ins and game actions remain compatible. No Tired Dogs files or game engine/layout changes. No live reads or writes were needed for this patch.
