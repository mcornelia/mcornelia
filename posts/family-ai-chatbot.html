FIELD GUIDE / OPENAI-CENTERED HOME AI

Build a Family AI ChatBot

ChatGPT + Codex + iMessage on an always-on Mac mini — without OpenClaw

A practical, security-first blueprint for a dedicated household Mac that automatically answers approved individual and group iMessage chats, while an administrator uses ChatGPT Remote and Tailscale to operate it from anywhere.

WHAT FAMILY AI COURIER IS. Family AI Courier is custom Python software created with Codex for this project. It runs as a small background service on the family Mac and connects Apple Messages to Codex. When a new message arrives in an approved chat, it reads a limited slice of that chat, asks Codex to write one reply, sends the reply through Messages, and records that the message was handled so it cannot be replayed or trigger a loop. It is not the AI model, not a chat app, and not a built-in ChatGPT, OpenAI, or Apple product. The complete source code, configuration examples, installer, tests, and documentation are available on GitHub.

In plain English: Messages is the inbox and outbox, Codex is the writer, and this background service carries each approved message between them. The dedicated Mac and its accounts give the household AI a separate identity.

Quick start

This guide builds the automatic version: a narrow local listener handles approved iMessage chats, while Codex uses the existing ChatGPT login for response generation. It needs neither OpenClaw nor a separate OpenAI API key.

Mode What it does Best use
A · Watch The local Python service opens one event-driven imsg watch stream for each explicitly approved chat. It ignores outgoing messages and baselines old history. Detect new direct and group iMessages without polling.
B · Think The service passes only bounded recent context to an ephemeral codex exec run authenticated through ChatGPT. The reply prompt forbids tools and consequential actions. Generate a short, personality-aware response without an API key.
C · Reply and operate The service sends once through Messages; launchd keeps it running. ChatGPT Remote, the Messages plugin, and Tailscale remain administrator tools. Automatic family chat with a private recovery path.

The 12-step version

  • Choose a base-model Mac mini for the most reliable always-on host; it should work fine for this setup. A MacBook Neo also works—see the clamshell section before buying adapters.
  • Create two local accounts: a standard “family AI” account for daily operation and a separate administrator/recovery account.
  • Create dedicated Apple, Google, and ChatGPT identities. Turn on strong MFA and record recovery details offline.
  • Update macOS; enable FileVault, the firewall, automatic security updates, Wake for network access, and restart after power failure. Leave automatic login off.
  • Sign the family AI account into Messages. Confirm a real iMessage address before proceeding.
  • Install the ChatGPT desktop app and use codex login to authenticate the bundled Codex CLI with the dedicated ChatGPT subscription. No API key is required.
  • Install imsg, grant its process Full Disk Access, and identify the exact direct and group chats whose participants have consented.
  • Ask Codex to audit and install the public Family AI Courier reference implementation. It watches only those chat IDs, stores high-water cursors, ignores outgoing messages, and supplies no more than the needed recent context.
  • Run each reply through ephemeral, read-only codex exec in an empty temporary directory, with strict tone, privacy, no-tool, and human-handoff instructions.
  • Install the background service as a launchd agent, keeping configuration and state owner-only. Preserve a one-command emergency stop.
  • Test a synthetic no-send response, then one approved direct chat, one consented group, duplicate/loop prevention, restart recovery, ChatGPT Remote, and Tailscale.
  • Write the runbook: how to stop the service, inspect its logs, remove a chat, revoke ChatGPT sessions, sign out of Messages, and reach the Mac physically.

HOW TO USE IT. Paste the prompt below into a new ChatGPT/Codex task on the dedicated Mac. It requires an interview, read-only discovery, a numbered plan, explicit approvals, and staged testing. Enter passwords and MFA codes directly in their own apps—never in the conversation.

- Produce a numbered architecture plan, a simple threat model, an exact change manifest, verification steps, and rollback steps. Wait for my approval before making changes.

Implementation rules:
- Prefer a standard “family AI” macOS user plus a separate recovery administrator. Keep FileVault, firewall, SIP, and automatic updates enabled. Do not enable automatic login.
- Install the ChatGPT desktop app, sign the bundled Codex CLI into the dedicated ChatGPT account, and verify a non-interactive no-send response. Do not create an API key.
- Use Tailscale for private remote administration; do not open router ports or expose Screen Sharing/SSH to the public internet.
- Clone and audit the Family AI Courier reference implementation from https://github.com/mcornelia/family-ai-chatbot. Watch only explicitly approved chat IDs, baseline existing history on first start, store a per-chat high-water row ID atomically, ignore outgoing messages, and restart watchers with bounded backoff.

- End with a one-page operator runbook, a monthly maintenance checklist, a permissions matrix, and a list of every file or setting changed.

1 · What this guide is—and is not

This is an OpenAI-centered automatic design. ChatGPT supplies the account and Codex entitlement; the local Python service supplies the event trigger and delivery discipline; Apple Messages supplies the transport. ChatGPT Remote, the official Messages plugin, and Tailscale are the administration plane.

IMPORTANT PRODUCT BOUNDARY. The Apple Messages plugin is not the automatic trigger. The background service independently watches approved local chats, invokes the ChatGPT-authenticated Codex CLI, and sends the result. Stopping it stops automatic replies without disabling ChatGPT or Messages.

What this guide deliberately avoids

  • No OpenClaw, broad agent bus, public webhook, router port-forward, or internet-exposed admin dashboard.
  • No private Messages framework, injection, or System Integrity Protection changes; the narrow listener uses the local imsg command.
  • No OpenAI API project, API key, or separate usage-based API billing. Codex authenticates through the dedicated ChatGPT subscription.
  • No access to every Messages conversation. Only exact, consented chat IDs are placed on the allowlist.
  • No silent enrollment of family members or group-chat guests. Consent and a visible trigger rule are part of the setup.

Reference system that informed this guide

The household installation audited for this article is a dedicated Mac mini running continuously under a dedicated account. Snapshot: August 2026.

2 · The architecture

Control plane versus message plane

Control plane: ChatGPT Remote, the optional Apple Messages plugin, Tailscale, Screen Sharing, and optional SSH. These administrator tools inspect, update, test, stop, and recover the system.

Automatic message plane: Apple Messages receives a text in an allowlisted chat. The service observes the new row, loads bounded context from that same chat, asks Codex for one short reply, sends it once, stores the new cursor, and ignores its own outgoing event.

DESIGN PRINCIPLE. Automate the conversation, not the computer. The reply run gets an empty temporary workspace, a read-only sandbox, no durable session, and instructions not to use tools or take outside actions.

One bot or several personalities?

One Messages identity can present several logical personalities, but it remains one contact/bubble.

  • Per-chat mapping: the grandparents’ group uses “Sage,” the game-night group uses “Spark,” and direct chats use the default.
  • Explicit selector: a message begins “@Sage …” or “@Spark …”. The reply begins “Sage:” so nobody mistakes a simulation for a separate person.
  • Temporary mode: “@Coach for this thread” changes persona until a timeout or reset command.

IDENTITY REALITY. Separate Apple Accounts or separate devices/logins are required for truly separate iMessage senders. Prompts alone can change voice and behavior, not the sender identity.

Google Voice can be its family-facing line for calls, voicemail, and Voice SMS, but it is not normally an iMessage sender. INDEPENDENT, NOT OWNERLESS. Put the Apple Account email and Voice number on one contact card. Name a human recovery administrator, store credentials in the family password manager, and label the two addresses.

Credential handling

  • Enter account passwords and MFA codes directly into System Settings, Messages, ChatGPT, Google, or Tailscale—not into a ChatGPT conversation.
  • Store recovery codes offline in the family’s password manager or secure physical record.
  • No OpenAI API key is required. Protect the dedicated ChatGPT account with MFA and review its signed-in devices and Remote hosts.
  • Review connected-app permissions quarterly and whenever a family member or administrator changes.

4 · Build the Mac mini host

Hardware and physical setup

  • A base-model Mac mini should work fine for ChatGPT, Messages, browser administration, and Tailscale. Upgrade only if you plan to run substantial additional services.
  • Prefer Ethernet. Keep Wi-Fi configured as a fallback, but avoid placing the host on a client-isolated or captive-portal network.
  • Use a small UPS if short power interruptions are common. FileVault plus no automatic login means a full reboot may still require local unlock.
  • Leave service clearance around the Mac, label its power and network cable, and document where a keyboard/display can be connected for recovery.
  • Maintain generous free space. Messages attachments, logs, Drive/Dropbox caches, macOS updates, and local backups can consume a small SSD surprisingly quickly.

First boot and account creation

  1. Connect a display and keyboard. Install all macOS updates before adding automation.
  2. Create the recovery administrator first. Then create a separate standard user for the family AI service.
  3. Sign in as the family AI user for the remaining app setup. Do not enable automatic login.
  4. Give the Mac a recognizable, non-sensitive name such as “Family-AI-Mac.” Avoid a street address or full family name.
  5. Set the correct time zone and enable automatic date/time. Remote access, security logs, calendar work, and scheduled maintenance depend on reliable time.

Security baseline

  • Turn on FileVault and escrow the recovery key safely.
  • Turn on the macOS firewall. Do not add broad “allow all incoming” exceptions.
  • Keep System Integrity Protection enabled.
  • Enable automatic update checks and rapid security responses. Schedule a monthly maintenance window for restarts and app updates.
  • Leave Guest User, remote Apple Events, and internet sharing off unless there is a documented need.
  • Restrict Screen Sharing and Remote Login to named administrators. Reach them over Tailscale, never public router ports.

Power and unattended behavior

In System Settings → Energy, configure the Mac mini to stay awake when the display is off, wake for network access, and restart after power failure. The display may sleep normally. In ChatGPT → Settings → Connections → Control this Mac or PC, enable the host keep-awake option while plugged in.

Command or configuration
# Optional verification only; review the output rather than copying it blindly
pmset -g custom
fdesetup status
/usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate

AVAILABILITY TRADE-OFF. FileVault and no automatic login are the right default. After some reboots, someone may have to unlock the Mac locally before Messages or ChatGPT can run. Solve that with a UPS, planned restarts, and a recovery contact—not by weakening disk security.

5 · Configure ChatGPT as the administrator workspace

Install and sign in

  1. Install the current ChatGPT desktop app for macOS on Apple silicon.
  2. Sign in with the dedicated ChatGPT account/workspace. Turn on MFA before enabling remote control.
  3. Add ChatGPT to Login Items for the family AI user and verify that it launches after a normal login.
  4. Create a dedicated project or task for setup notes. Keep secrets out of the task; link to a password-manager entry instead.

Optionally enable the Apple Messages plugin

  1. Open ChatGPT desktop → Plugins.
  2. Find Apple Messages and select the plus button to enable it.
  3. Start a new Codex or ChatGPT Work task and ask for a harmless read-only search first.
  4. Grant macOS permissions only when prompted. Review exactly which app is requesting Full Disk Access or Automation.
  5. Keep per-send approval enabled for administrator-initiated plugin sends. This approval setting is separate from the automatic reply path.

USE IT FOR ADMINISTRATION. The plugin is ideal for “find the last message from Dad,” “draft a special reply,” or “send this approved text.” The background service handles ordinary automatic replies; the plugin does not need to remain involved in that loop.

Set up ChatGPT Remote

  1. On the host, install the latest ChatGPT desktop app and leave the Mac awake and online.
  2. On the administrator’s phone, install the latest ChatGPT mobile app and sign into the same ChatGPT account and workspace.
  3. On the host, open ChatGPT → Settings → Connections → Control this Mac or PC → Set up or Add.
  4. Scan the QR code with the phone and complete MFA.
  5. On the phone, open the sidebar → Remote and select the host.
  6. On the host, review Remote settings: Keep Mac awake, Computer Use, and the Chrome extension. Enable only what the administrator needs.
  7. Test a read-only task, then a task that requires an approval. Confirm that approval appears on the phone and that choosing Sleep actually makes the host unavailable.

WHAT REMOTE CHANGES. Remote exposes the selected host’s files, plugins, credentials, permissions, and tools through OpenAI’s relay. It does not require a public inbound port. Treat Remote access like sitting at that Mac: protect the ChatGPT account and phone accordingly.

6 · Configure Messages

  1. Sign the dedicated Apple Account into Messages. Do not import a person’s personal Messages history.
  2. In Messages settings, confirm “You can be reached for messages at” includes the dedicated Apple Account email.
  3. Send a manual iMessage from a family member to that address and reply manually. Confirm the bubble is blue and the sender is the expected bot contact.
  4. Create the intended group chat in Messages and obtain consent from every participant. Explain that messages may be sent to an OpenAI model for response generation.
  5. Give the agent contact a clear name and avatar so it reads as a distinct household identity; do not impersonate a human family member.
  6. If SMS/MMS/RCS forwarding is required, use a compatible iPhone with the same Apple Account. Google Voice does not replace that Apple relay.

NEVER DISABLE SIP FOR THIS DESIGN. The service uses ordinary user-space commands and normal macOS privacy permissions. Private-framework injection and SIP changes are unnecessary and materially weaken the host.

7 · The automatic iMessage loop

What happens after setup

  1. A family member sends an individual or group iMessage to the dedicated Apple Account.
  2. The always-on service receives the event only if that exact chat ID is on its allowlist. Old messages are baselined on first launch and are never replayed.
  3. It reads a small, fixed amount of recent history from that same chat and labels group speakers before constructing the reply prompt.
  4. Codex runs non-interactively with the cached ChatGPT login, an empty temporary working directory, an ephemeral session, and a read-only sandbox.
  5. The service sends the final short response through Messages and records its new high-water cursor. Outgoing events are ignored, preventing self-reply loops.

Intentional limits

  • Chats that are not explicitly allowlisted receive no automatic response.
  • Attachments may be acknowledged and handed to a human rather than interpreted automatically.
  • The reply run may converse, but it must not purchase, schedule, change files, browse private services, or make consequential decisions.
  • A successful iMessage response is not proof that ChatGPT Remote, Tailscale, or the optional Messages plugin is healthy; monitor those components separately.

Why is the local service necessary?

The Messages plugin is an excellent administrator tool, but it does not provide the unattended event loop described here. The local service runs continuously under launchd, opens an imsg watch stream only for allowlisted chats, keeps a saved high-water cursor so old messages are not replayed, limits context to the triggering chat, invokes codex exec, sends once, and ignores its own outgoing event. Codex writes the response; the service handles the event, state, safety boundaries, and delivery.

8 · Pilot and verification

Test the automatic workflow

  • Send a harmless iMessage to the dedicated Apple Account from one family member.
  • Before enabling live sends, run the service’s synthetic test command and confirm Codex returns only a short reply.
  • Start it in dry-run mode and send one harmless message from an allowlisted family member. Confirm the log records a proposed reply but sends nothing.
  • Enable live mode, send one new direct message, and verify exactly one response appears in the correct chat.
  • Repeat with one consented group chat. Confirm the latest speaker is identified correctly and only that group receives the reply.
  • Send a message from the bot account and confirm the outgoing event is ignored.
  • Restart the service, then restart and unlock the Mac. Verify saved cursors prevent old-message replay and launchd returns it to running state.

Acceptance criteria

  • A new message in an allowlisted chat receives one automatic reply without an administrator starting a task.
  • An administrator can reach the Mac through ChatGPT Remote and can recover the desktop through Tailscale.
  • The model sees only bounded context from the triggering chat and does not use tools or take outside actions.
  • Outgoing messages, old history, and chats outside the allowlist do not trigger replies.
  • Stopping the LaunchAgent immediately stops automatic replies while leaving Messages usable.
  • The household understands that this is an automatic conversational assistant with explicit safety and human-handoff limits.

9 · Personalities and routing

Family AI Courier supports several logical personalities behind one Messages identity. A participant puts one exact selector at the start of a message—for example, @Sage for a calm practical voice or @Spark for a playful creative voice. The local service, not iMessage or Codex, parses that first token and chooses an owner-configured personality description.

Configure personalities

  1. Add a personas map to the service’s owner-only config.json. Each entry has a selector key, display name, short description, and optional reply-label or signature setting.
  2. Optionally set a global or per-chat default personality. Without a default or selector, the service uses its ordinary assistant name and description.
  3. Use @help to list the configured choices. Unknown, empty, or multiple selectors receive a deterministic local help response without invoking Codex.
  4. A recognized selector is removed from the newest message before the bounded transcript is sent to Codex. Matching is exact and case-insensitive; the rest of the message remains ordinary conversation.
  5. By default the outgoing reply begins with the active display label, such as Sage:, because all personalities still appear in the same Apple Messages contact bubble.

Start with the repository’s example Sage and Spark entries, then edit their names and descriptions. Run make check, keep dry_run enabled, and test the default route, each selector, @help, an unknown selector, and a consented group chat before enabling live sends.

PERSONALITY IS NOT PERMISSION. Every personality inherits the same allowlist, bounded same-chat context, tool-free Codex run, safety rules, human handoffs, and emergency stop. A message cannot use an @name to gain tools or reach another chat. If a logical agent truly needs broader capabilities, make it a separate administrator-started workflow.

ONE CONTACT, MANY VOICES. These are routed personalities, not separate Apple identities. Create separate Apple Accounts only when truly separate senders are necessary.

10 · Dedicated Google services

Give the household AI its own Google Account for Gmail, Calendar, Drive, and optional Voice rather than borrowing a family member’s. Use a separate browser profile, enable MFA, and share only the specific family resources it needs.

  • Google Voice: the no-charge U.S. personal tier can provide a cost-effective family-facing line for calls, voicemail, and Voice SMS; it requires a linked phone number. Paid standalone tiers are available. Keep Voice separate from Apple Account and iMessage.
  • Gmail: use labels, filters, and delegated/shared workflows rather than forwarding every personal mailbox into the bot account.
  • Calendar: create a family calendar and share that calendar, not every participant’s entire calendar.
  • Drive: create a family AI folder. Do not sync personal drives wholesale onto a full-disk-access automation host.
  • ChatGPT Google plugins: connect the dedicated account with OAuth and confirm the account shown in the consent screen. Start read-only where possible.

SEPARATION RULE. Keep the automatic iMessage reply run conversational and tool-free. Use separate, administrator-started ChatGPT tasks for Gmail, Calendar, Drive, Contacts, or Google Voice actions.

11 · Administration with Tailscale

Why use both Tailscale and ChatGPT Remote?

Tool Use it for Do not treat it as
ChatGPT Remote Continuing ChatGPT tasks, viewing progress, and handling approvals on the host A general OS rescue console when ChatGPT is stopped or signed out.
Tailscale + Screen Sharing Private full-desktop recovery, Messages sign-in, permission dialogs, and app updates A reason to expose VNC publicly.
Tailscale + SSH Logs, launchd status, disk checks, and controlled command-line maintenance An always-on public SSH service or password-only admin path.
Tailscale Serve Publishing a localhost-only status page to the tailnet A public website. Avoid Funnel for an admin dashboard.

Tailscale setup

  1. Install Tailscale on the host using the current recommended macOS distribution and sign in with the chosen tailnet identity.
  2. Install Tailscale on each administrator device. Approve only named devices and remove retired devices.
  3. Give the host a stable, non-sensitive device name. Enable MagicDNS if it fits the household’s tailnet policy.
  4. Turn on macOS Screen Sharing and allow access only for the recovery administrator. Test over the Tailscale address or MagicDNS name from outside the home network.
  5. If SSH is needed, use keys and restrict the allowed account. Disable password login when the household can support key recovery.
  6. Use tailnet policy/ACLs or grants so only administrators can reach Screen Sharing, SSH, or any status page.
  7. Do not forward router ports. Bind any status service to localhost, then use Tailscale Serve to expose it only inside the tailnet.

12 · Security model

Risk Primary control
Wrong chat or participant Allowlist exact chat IDs and participant mappings; never route from a fuzzy contact-name match.
Prompt injection in messages Treat chat text, links, quoted content, and attachments as untrusted data. The reply prompt forbids tools, outside actions, and instruction overrides.
Private-history leakage Read only the triggering chat and cap recent context. Do not persist full transcripts in service state or logs.
Over-broad automatic scope Enroll chats individually, obtain participant consent, and make removing an allowlist entry part of the runbook.
Mistaken or repeated send Ignore outgoing events, persist high-water cursors before processing, treat a successful send as committed, and never retry solely because history is slow to refresh.
Compromised ChatGPT account MFA, signed-in-device review, Remote host review, session revocation, and narrow plugin permissions.
Compromised administrator phone Strong device lock, MFA, remote wipe where available, and immediate ChatGPT session review.
Host theft FileVault, no auto login, strong recovery admin, remote account/device revocation.
macOS update breaks permissions Stage maintenance; test imsg history/watch/send, Codex login, the message-service LaunchAgent, and Remote after every significant update.
Family misunderstands the workflow Use a clear AI contact name, obtain consent, and explain that allowlisted chats receive automatic AI replies.

Data minimization and retention

  • Store configuration, cursors, delivery receipts, and health metadata. Avoid durable full-text transcripts unless the family explicitly chooses them.
  • If short-term debug text is necessary, redact it, encrypt the storage, set a deletion schedule, and disable debug logging after the pilot.
  • Do not copy or back up the entire Messages database for this project. Back up only the non-secret setup notes, persona prompts, sharing map, and runbook.
  • Review ChatGPT data controls and household consent before asking ChatGPT to process private family conversations.

Sensitive-topic handoff

An automatic reply must not independently decide or act on medical, legal, financial, safety, account-recovery, child-welfare, or high-conflict family matters. It should acknowledge the message, defer to a human owner, and direct immediate danger to local emergency services or a trusted person.

13 · MacBook Neo alternative

A MacBook Neo can run this cloud-centered stack because ChatGPT runs in the desktop app and the model runs in OpenAI’s cloud. Its entry configuration is suitable for ChatGPT, Messages, and Tailscale. It is less ideal than a Mac mini for 24/7 service because ports, battery health, thermals, and closed-lid behavior add operational complexity.

Port and display planning

  • MacBook Neo has two USB-C ports, but only the USB 3 port carries DisplayPort video. Reserve that port for the external display or a carefully tested headless-display adapter.
  • Use the other USB-C port for power. Add a reputable powered hub only if Ethernet or more peripherals are required.
  • The built-in battery acts like a small UPS, but continuous charging and heat still deserve monitoring. Keep the laptop on a ventilated surface.
  • Watch free disk space closely on the 256 GB model; Messages attachments and sync caches should not be allowed to grow without review.

Keeping it awake with the lid closed

OFFICIAL REQUIREMENT. For reliable closed-lid operation, connect power, an external display, and previously connected keyboard and mouse. OpenAI’s Remote guidance likewise says a Mac laptop must remain open and powered, or use an external display when the lid is closed.

  1. While the lid is open, connect power and the external display to the correct USB-C/DisplayPort port.
  2. Pair or connect the keyboard and mouse, and confirm the external display is authorized and working.
  3. In System Settings → Battery → Options, enable “Prevent automatic sleeping on power adapter when the display is off” and “Wake for network access” as appropriate.
  4. In ChatGPT → Settings → Connections → Control this Mac or PC, enable “Keep this Mac awake” while plugged in.
  5. Close the lid and test Screen Sharing, Tailscale SSH, ChatGPT Remote, Messages, the message-service LaunchAgent, and one automatic reply for at least an hour.
  6. Reopen the lid for macOS updates, permission dialogs, FileVault unlock, or any sign-in repair.

HEADLESS ADAPTER CAVEAT. A display-emulator/dummy adapter may satisfy clamshell mode without a real monitor, but that is a practical workaround rather than Apple’s documented configuration. Use a reputable adapter, test wake/restart behavior, and keep a real display available for recovery.

ABOUT CAFFEINATE. caffeinate is useful for temporary open-lid maintenance sessions, but do not rely on it to defeat lid-close sleep. Closed-clamshell service should meet Apple’s power/display requirements and pass a real restart-and-wake test.

14 · Operator runbook

Emergency stop

  • Stop or unload the message-service LaunchAgent to stop all automatic replies immediately. Confirm its state is no longer running.
  • Remove a chat from the service allowlist when only one conversation should stop.
  • Quit ChatGPT/Codex or run codex logout if the model session itself is in question.
  • Use Tailscale Screen Sharing to sign out of Messages or ChatGPT if an account may be compromised.
  • Revoke affected Apple, Google, ChatGPT, or Tailscale sessions from a trusted device when account security is involved.

Weekly checks

  • ChatGPT Remote shows the host online.
  • Tailscale is connected and private administrative access works.
  • Messages remains signed into the dedicated Apple Account.
  • The service is running, its error log is quiet, the configured backend is Codex, and a synthetic no-send response works.
  • Disk space remains comfortable and macOS shows no unexpected privacy-permission prompts.

Monthly maintenance

  • Install staged macOS, ChatGPT, Tailscale, and browser updates.
  • After restart and local unlock, test ChatGPT Remote, Tailscale, imsg history/watch/send, Codex login, and one automatic reply.
  • Review the chat allowlist, participant labels, administrators, tailnet devices, Google sharing, plugins, and Remote hosts.
  • Confirm the FileVault recovery process, account-recovery information, and physical-access plan are still current.

16 · Advanced and optional extensions

Once the automatic reply loop is quiet, predictable, and easy to stop, the same household Mac can support useful companion services. Keep each extension separately configurable, backed up, and recoverable.

Add a home maintenance tracker

Home Maintenance Tracker is a private-by-default, self-hosted application for remembering how an entire property is cared for. A household can add plants, appliances, mechanical systems, safety equipment, and exterior structures; attach recurring, seasonal, one-time, paused, or unscheduled maintenance plans; log completed work; and see what is overdue or due soon. It also supports maintenance history, photos, outdoor weather, email digests, and nightly SQLite backups.

The tracker is a companion application, not part of the iMessage reply loop. Install it on the same always-on Mac or another trusted host, keep its database and photos outside the source repository, and back it up independently.

Docker Compose quick start

Run from a clone of the repository
cp .env.example .env
mkdir -p local-data local-backups
docker compose up --detach --build

Open http://localhost:4173, create the shared household passphrase, choose the household name under Settings, and configure /backups as the Docker backup destination. Other devices on the trusted LAN can use the host’s .local name or LAN IP.

Native macOS quick start

The native path requires Node.js 22 or newer and pnpm 11. It installs a per-user launchd service that runs the compiled Node server and SQLite without leaving Docker, Vite, or the package manager resident.

Run from a clone of the repository
cp .env.example .env
chmod 600 .env
# Set an absolute private YARD_TRACKER_DATA_DIR in .env
pnpm macos:install
pnpm macos:status

Before relying on either path, configure a dedicated backup location, create a manual backup, and test a restore. The repository’s Docker and native-Mac runbooks cover updates, rollback, LAN access, and recovery.
